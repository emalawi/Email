Overview

Smartbase Email is a Cloudflare Workers application for branded verification emails, Google-based sign-in, project API keys, optional device limits, offline database copy, and mass email broadcasts with open/unsubscribe tracking.

Static assets (including this documentation) are served publicly from the Worker’s asset binding. No login is required to read these pages.

Deploy

  1. Create or update D1 tables (safe to run more than once):
npx wrangler d1 execute smartbase-db --remote --file=migrations/0002_controls.sql
  1. Ensure secrets exist: CREDENTIAL_KEY (64 hex characters) and Gmail-related secrets. SMARTBASE_URL is set in wrangler.jsonc.
  2. Deploy:
npx wrangler deploy

Or push to GitHub if Cloudflare is connected to build and deploy from the repository.

Sign-in options

  • Default Google app — use the platform’s Google OAuth client.
  • Your own Google app — supply Client ID and Secret.
  • Custom sign-in domain — Google redirects through https://your-domain/__smartbase/... so the flow stays on your brand.

The client SDK can send a stable device id and accept baseUrl: 'https://your-domain/__smartbase'.

Users & storage

You can store users in:

  • Platform default storage.
  • Your Smartbase database — empty-database template or a custom table plus the smartbase-data.js SDK. The platform calls your Smartbase /apiv1 API with write and read keys (one request per sign-in). Smartbase rate limits (e.g. 20 requests/minute, 2,000/day) therefore also limit sign-ins when using this mode.
  • Your own server — via a signed gateway.

Account control

“One account, one device” can run in two modes:

  • Monitor — count usage only; no hard block on duplicates.
  • Enforce — a device may only be tied to one account; further attempts return an error.

Broadcasts

Supports test emails and mass sends with sent/opened tracking and unsubscribe links. Sent from the platform Gmail account subject to configured caps.

SDK files (served from /public)

  • smartbase.js — sign-in button; sends a stable device id; supports custom baseUrl.
  • smartbase-data.js — server-side helper to define how users are written to a custom table.

Example pages: SDK demo.

Sign-in error codes

  • device_limit — device already used by another account (enforce mode).
  • device_required — enforce mode but no device id was sent (update smartbase.js).
  • Plus existing platform error codes returned by the auth flow.

Limits

  • Broadcasts: up to 500 recipients per broadcast (BROADCAST_MAX_RECIPIENTS).
  • Up to 400 emails per project per 24 hours (BROADCAST_DAILY_LIMIT), subject to configuration.
